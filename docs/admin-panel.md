# Admin Panel

## Доступ

Админка поднимается тем же процессом, что и бот, и по умолчанию слушает порт `1488`. Авторизация выполняется по логину и паролю из `bot_settings`. Пароль хранится в хеше; legacy plaintext при успешном входе автоматически обновляется до hash.

Защита, которая реально есть в коде:

- session cookie `HttpOnly`;
- `SameSite=Lax`;
- таймаут сессии `8 часов`;
- CSRF для всех `POST`, кроме webhook-роутов;
- ограничение попыток входа по IP.

## Разделы

### Dashboard

- сводная статистика;
- проблемные пользователи;
- расчёт активных/истекших платных и trial-подписок использует тот же классификатор, что и раздел `Users`, чтобы статусы не расходились между страницами;
- активный доступ без оплаченной транзакции (промокод или ручная выдача) показывается отдельно как бесплатный, а не как платный;
- все оплаченные покупки за всё время с полной датой и временем, последние платежи показываются сверху;
- графики по дням.

### Users

- список пользователей с раздельными статусами подписки: активная платная, истекшая платная, активная пробная, истекшая пробная, без подписки, забанен;
- фильтры по каждому статусу без смешивания истекших подписок с пользователями без подписки;
- ban / unban;
- revoke всех ключей;
- удаление профиля и доступов с сохранением платёжного журнала;
- массовый выбор строк текущей страницы: ban, unban, revoke и удаление профилей; удаление требует отдельного текстового подтверждения;
- ручная выдача подписки;
- диагностика по конкретному пользователю;
- экспорт CSV.

### Keys

- сгруппированный список ключей по пользователям;
- `plan_id=0` считается пробным только пока срок от создания ключа соответствует настроенной длительности trial; продлённый администратором ключ показывается как бесплатная подписка с ручным начислением дней;
- корректировка срока;
- синхронизация connection string с 3x-ui;
- исправление параметров клиентов;
- комплексное обслуживание;
- показ и копирование VPN-ключа, proxy-link или subscription-link.
- массовый выбор строк и отзыв ключей; одна глобальная строка включает все показанные в ней серверные ключи.

### Profit

- выручка периода всегда строится из оплаченных транзакций по дате фактической оплаты и не вводится вручную;
- порядок расчёта: из всей выручки Влад платит налог `9%`, затем вычитаются расходы на серверы, после чего остаток делится Богдану `40%` и Владу `60%`;
- денежные суммы округляются до копейки, а сумма долей точно равна распределяемому остатку;
- выплаченную фиксацию нельзя отменить;
- история показывает сверку зафиксированной выручки с текущим платёжным журналом.

### Settings

- сверху расположены крупные ссылки на серверы, подписку Happ, лимит IP, платежи, ботов и безопасность; дополнительные переходы собраны в раскрывающееся меню, чтобы элементы управления не сливались;
- общие тексты и ссылки;
- токены ботов и параметры панели;
- payment settings;
- отдельный блок подписки Happ: название, информационная строка, период автообновления, автовыбор и маршрутизация;
- отдельный блок `Лимит IP`: включение контроля, допустимое количество IP, окно свежей активности, льготный период после предупреждения, журнал превышений, досрочное принудительное ограничение предупреждённого пользователя, а также индивидуальное и массовое снятие активных ограничений без отключения мониторинга;
- если превышений IP ещё не было, вместо пустой таблицы показывается сообщение об отсутствии событий; таблица появляется автоматически после первого события;
- IP объединяются по всей подписке пользователя и одинаковый внешний IP на разных серверах считается один раз; предупреждение создаётся после двух превышений подряд, а неполный снимок панелей не изменяет состояние;
- при автоматическом или досрочном ограничении заданный `limitIp` выставляется на всех XUI-конфигурациях пользователя; подписка полностью не приостанавливается;
- изменение `ip_limit_max_ips`, `ip_limit_activity_window_minutes` и `ip_limit_warning_grace_hours` вступает в силу после общей кнопки `Сохранить изменения`;
- trial и referral settings;
- backup/import с отдельными опциями включения и применения `.env`;
- XUI-хосты и MTG-хосты;
- планы;
- payment method rules;
- промокоды на глобальную подписку с отдельным статусом включения, лимитом, сроком действия, счётчиком применений и действиями pause/start/delete;
- незавершённая выдача промокода сохраняет фиксированную дату окончания и может быть безопасно продолжена повторным вводом того же кода;
- включение/отключение global plans.

Support-бот при этом продолжает работать отдельно от админки:

- создаёт `forum topic` в группе поддержки;
- сохраняет тикеты и историю сообщений в SQLite;
- восстанавливает тикет при потере Telegram topic.

Отдельно важно:

- настройка `Спрашивать Email перед оплатой YooKassa` относится только к оплате через YooKassa;
- если опция выключена, бот не спрашивает email перед оплатой и использует fallback `receipt_email` для чека;
- fallback `receipt_email` должен быть реальным email, а не placeholder вроде `example@example.com`; иначе YooKassa скрывается из доступных способов оплаты;
- VPN-тарифы для пользователей работают как глобальная подписка `ALL`: пользователь получает одну `/sub/...` ссылку, а подробный список отдельных XUI-ключей в пользовательском боте не показывается.
- XUI-тарифы можно добавлять только в глобальном блоке `ALL`; backend админки отклоняет создание или ручную выдачу per-host XUI-тарифов.
- Per-host XUI-ключи в БД остаются техническими записями для 3x-ui и subscription API, а не отдельными пользовательскими продуктами.
- для 3x-ui v3 в карточке XUI-хоста можно указать `API Token`; если поле заполнено, `py3xui 0.7.0` использует штатный `Authorization: Bearer`, иначе бот выполняет CSRF/cookie-login;
- один и тот же URL 3x-ui можно добавить несколькими XUI-хостами, если у них разные `Inbound ID`/протоколы;
- при добавлении/редактировании XUI-хоста preflight создаёт и удаляет тестового клиента, поэтому неверный inbound, token или CSRF/API-доступ блокируются до сохранения.
- ссылки клиентов берутся через официальный 3x-ui clients API; для Hysteria/Hysteria2 бот использует raw JSON API, потому что идентификатор клиента в 3x-ui хранится в поле `auth`.

### Updates

- проверка версии по GitHub;
- force-update приложения.

## Админские действия с прод-эффектом

Особенно аккуратно использовать:

- удаление хоста;
- удаление пользователя;
- revoke ключей;
- backup import;
- update из панели.

Эти действия не только меняют БД, но и могут удалять клиентов на внешних панелях или перезапускать приложение.
Удаление профиля не удаляет строки `transactions`: финансовая история должна
оставаться неизменной, иначе пересчитываются выручка и уже закрытые периоды.
